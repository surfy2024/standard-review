# 标准审查技能使用指南

## 快速开始

### 1. 基本审查

最简单的使用方式是直接调用技能并提供文档路径：

```
请审查这份标准草稿：@path/to/standard.docx
```

技能会自动：
1. 分析文档样式
2. 执行自动化检查
3. 生成审查报告

### 3. 详细审查

如果需要更详细的审查结果，可以运行：

```bash
python scripts/check_standard.py <input.docx> --output result.json --pretty --analyze-styles
```

**参数说明**：
- `--output`：输出 JSON 结果文件
- `--pretty`：格式化 JSON 输出
- `--analyze-styles`：分析文档样式

## 常见问题

### Q1: 为什么有些段落被误判为标题？

**原因**：
- 文档使用了非标准的样式名称
- 段落内容符合标题的某些特征（如编号格式）

**解决方法**：
1. 运行样式分析，了解文档的样式体系
2. 查看误判段落的样式名称和内容特征
3. 根据实际情况调整识别逻辑

### Q2: 如何处理"无标题条"样式？

**说明**：
"无标题条"样式通常用于正文内容，不应作为标题处理。

**处理方式**：
- 脚本会自动识别并排除"无标题条"样式
- 如果仍被误判，可以检查样式名称是否包含"无标题条"关键词

### Q3: 数字与单位之间一定要加空格吗？

**依据**：根据 GB/T 1.1-2020，数字与单位符号之间应留半角空格。

**示例**：
- ✅ 正确：10 m、5 L、24 h
- ❌ 错误：10m、5L、24h

**例外情况**：
- 百分号：50%（数字与%之间不加空格）
- 平面角单位：17.25度（可使用汉字单位）

### Q4: "应"和"宜"有什么区别？

**依据**：根据 GB/T 1.1-2020：

| 能愿动词 | 含义 | 使用场景 |
|---------|------|----------|
| 应 | 强制要求 | 必须满足的要求 |
| 宜 | 推荐 | 建议遵守但非强制 |
| 可 | 允许 | 许可选择的行为 |
| 能 | 能力 | 陈述可能性或能力 |

**常见错误**：
- ❌ "应考虑" → ✅ "宜考虑"
- ❌ "应避免" → ✅ "宜避免"
- ❌ "必须" → ✅ "应"

### Q5: 前言必须包含哪些内容？

**依据**：根据 GB/T 1.1-2020，前言应包含以下内容：

1. **文件起草依据声明**
   - "本文件按照GB/T 1.1—2020的规定起草"

2. **提出部门**
   - 提出本文件的单位

3. **归口单位**
   - 负责本文件的技术归口单位（技术委员会）

4. **起草单位**
   - 负责起草本文件的具体单位

5. **主要起草人**
   - 参与起草的主要人员名单

6. **代替关系**（如适用）
   - 如本文件代替某先前文件，应说明代替关系及主要技术变化

## 最佳实践

### 1. 审查前准备

- ✅ 确认文档格式为 .docx
- ✅ 了解文档的样式体系
- ✅ 准备好 GB/T 1.1-2020 规则文件

### 2. 审查过程

- ✅ 先运行样式分析，了解文档特点
- ✅ 再运行自动化检查
- ✅ 结合规则文件进行人工判断

### 3. 审查后处理

- ✅ 按优先级处理问题（错误 > 警告 > 建议）
- ✅ 记录修改内容和原因
- ✅ 复审修改后的文档

### 4. 特殊情况处理

- 📌 对于特殊格式的标题，可以手动标记
- 📌 对于非标准的编号方式，可以调整识别参数
- 📌 对于引用文献中的特殊表述，可以忽略警告

## 进阶技巧

### 自定义样式识别

如果文档使用了特殊的样式体系，可以修改脚本中的样式识别逻辑：

```python
# 在 check_standard.py 中修改 _is_heading_style 方法
def _is_heading_style(self, style_name: str) -> bool:
    # 添加自定义样式名称
    custom_heading_styles = ["自定义标题1", "自定义标题2"]
    
    for style in custom_heading_styles:
        if style in style_name:
            return True
    
    # 其他判断逻辑...
```

### 批量审查

可以编写脚本批量审查多个文档：

```python
import os
from pathlib import Path

# 批量审查
for docx_file in Path("standards/").glob("*.docx"):
    print(f"审查：{docx_file}")
    # 运行审查脚本...
```

### 结果对比

可以对比不同版本的审查结果：

```python
import json

# 加载两个版本的结果
with open("v1_result.json") as f:
    v1 = json.load(f)

with open("v2_result.json") as f:
    v2 = json.load(f)

# 对比问题数量
print(f"V1 问题数：{v1['total_issues']}")
print(f"V2 问题数：{v2['total_issues']}")
```
