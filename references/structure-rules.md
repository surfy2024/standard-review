# GB/T 1.1-2020 结构与要素规则

## 要素分类体系

### 按功能分类

| 类别 | 说明 | 典型要素 |
|------|------|----------|
| 资料性要素 | 提供有助于理解或使用文件的附加信息 | 封面、目次、前言、引言、参考文献、索引 |
| 规范性要素 | 规定文件需要满足的要求或确立的规则 | 范围、规范性引用文件、术语和定义、核心技术要素、附录（规范性） |

### 按存在状态分类

| 类别 | 说明 |
|------|------|
| 必备要素 | 文件中必须存在的要素 |
| 可选要素 | 根据文件的具体需求选择是否纳入的要素 |

## 必备要素清单

以下要素在所有标准化文件中必须存在：

1. **封面** — 资料性要素，必备
2. **前言** — 资料性要素，必备
3. **范围** — 规范性要素，必备
4. **核心技术要素** — 规范性要素，必备

以下要素为必备或可选（视文件内容而定），但即使无内容也必须列出该要素标题并声明：

5. **规范性引用文件** — 有则列出引用文件清单，无则声明"本文件没有规范性引用文件。"
6. **术语和定义** — 有则列出术语定义，无则声明"本文件中没有需要界定的术语和定义。"

## 可选要素清单

- **目次** — 资料性要素，可选（文件页数较多时宜设置）
- **引言** — 资料性要素，可选（用于说明编制背景、技术动因或特殊说明，不得包含规范性技术条款）
- **附录** — 可为规范性或资料性，可选
- **参考文献** — 资料性要素，可选
- **索引** — 资料性要素，可选
- **图和表的清单** — 资料性要素，可选

## 要素排列顺序

标准化文件的要素应按以下顺序排列：

```
封面 → 目次（可选）→ 前言 → 引言（可选）→
正文（范围 → 规范性引用文件 → 术语和定义 → 其他规范性要素/核心技术要素）→
附录（可选）→ 参考文献（可选）→ 索引（可选）
```

## 层次结构（五级嵌套体系）

| 层级 | 编号方式 | 格式示例 | 规则说明 |
|------|----------|----------|----------|
| 章 | 阿拉伯数字 | `1`、`2`、`3` | 最高功能单元，每章应有明确主题且彼此逻辑并列或递进 |
| 条 | 章号.条号 | `3.1`、`3.2.1`、`3.2.1.1` | 技术要求的基本承载单位，每个条应表述单一、完整、可验证的内容。条最多分到第五层次（如 X.X.X.X.X） |
| 款 | 不编号，破折号引导 | `—` | 必须隶属于某一条 |
| 项 | 字母加右括号 | `a)`、`b)`、`c)` | 必须隶属于某一"款"，使用小写拉丁字母，右括号用半角 |
| 段 | 无编号自然段 | — | 以无编号自然段呈现，是条或款下的进一步说明 |

### 层次编号规则

- 章编号从"1"开始连续编号
- 条的编号由所属章号和本条序号组成，用下脚点分隔
- 附录中的章/条编号使用附录字母前缀（如附录A中：A.1、A.1.1）
- 项的编号使用小写拉丁字母：a)、b)、c)...，不使用 i)、j) 等易与数字混淆的字母（可选）

### 禁止情形

- 禁止出现"孤立的"款或项（即款必须隶属于条，项必须隶属于款）
- 禁止在段的下面直接设条（即"悬挂段"），应在条标题下设段或直接在条下设条
- 禁止仅有一个条时使用条编号（如不应出现"3.1"而下方无"3.2"）——此时直接在章下设段即可

## 前言编写要求

### 必备内容

前言必须包含以下内容（按顺序）：

1. **文件起草依据声明**：说明本文件按照GB/T 1.1—2020的规定起草
2. **文件与GB/T 1的关系说明**：说明本文件是GB/T X《……》的第几部分/或独立文件
3. **提出部门**：提出本文件的单位
4. **归口单位**：负责本文件的技术归口单位（技术委员会）
5. **起草单位**：负责起草本文件的具体单位
6. **主要起草人**：参与起草的主要人员名单
7. **代替关系**：如本文件代替某先前文件，应说明代替关系及主要技术变化

### 可选内容

- 专利声明（如涉及专利）
- 标准编制说明的说明
- 附录性质说明（规范性/资料性）

## 无内容要素的声明规范

### 无规范性引用文件

仍须列出"规范性引用文件"标题，并在引导语后写：

> 本文件没有规范性引用文件。

### 无术语和定义

仍须列出"术语和定义"标题，并写：

> 本文件中没有需要界定的术语和定义。

## 附录编写规则

- 附录按其在正文中提及的先后顺序，用大写拉丁字母从A开始编号（附录A、附录B...）
- 附录应标明性质：规范性（normative）或资料性（informative）
- 附录中的章、条编号使用附录字母前缀（如A.1、A.2、B.1.1）
- 附录中的图、表、公式编号使用附录字母前缀（如图A.1、表B.2、公式(C.1)）
- 跳过字母I和O以避免与数字混淆

## 范围要素编写要求

- 范围应简要说明文件的主要内容
- 应说明文件的适用对象和适用领域
- 范围的表述应简洁，不包含要求型条款
- 标准表述格式："本文件规定了……""本文件适用于……""本文件不适用于……"

## 规范性引用文件编写要求

### 引导语（固定表述）

> 下列文件中的内容通过文中的规范性引用而构成本文件必不可少的条款。其中，注日期的引用文件，仅该日期对应的版本适用于本文件；不注日期的引用文件，其最新版本（包括所有的修改单）适用于本文件。

### 列表要求

- 按文件编号的字母/数字顺序排列
- 每个引用文件独占一行
- 注日期引用：包含年份，格式如 `GB/T XXXXX—20XX`
- 不注日期引用：不含年份，格式如 `GB/T XXXXX`
- 先列国家标准，再列行业标准，再列国际标准
